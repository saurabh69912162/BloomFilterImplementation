Why this Bloom filter is built this way

mmh3, double hashing, the sizing formulas, and a concrete walkthrough with the name saurabh.

← Interactive demo

The filter stores no names

A Bloom filter keeps a fixed array of m bits (initially all 0). It does not store strings like “saurabh” anywhere-only which bits should be 1. Membership is probabilistic: a query can say “definitely not in the set” or “maybe in the set.”

Why MurmurHash3 (mmh3) is used

  • Speed: Very fast in software-important when you insert or query millions of keys.
  • Distribution: Output bits are well spread out, so indices into the bit array behave like pseudo-random positions (fewer accidental clumps than a weak hash).
  • Not cryptographic: Bloom filters do not need collision resistance against an attacker-only good mixing-so a non-crypto hash is appropriate.
  • Stable seeds: We call mmh3 with fixed seeds (e.g. 0 and 1) so the same string always maps to the same bit positions.

Why double hashing is used

The classic Bloom filter needs k different hash values per key. Maintaining k fully independent hash functions is awkward. Double hashing builds all k positions from only two base hashes, h₁(x) and h₂(x): 

hᵢ(x) = ( h₁(x) + i · h₂(x) ) mod m,   for i = 0, 1, …, k − 1

Here h₂ is chosen so it is never 0 modulo m (in this project: h₂ ∈ [1, m − 1]), so the k indices do not collapse to one point. This pattern is standard, cheap, and works well in practice.

Mathematical sizing (this demo)

Target: about n keys and desired false-positive rate p (here n = 100 000, p ≈ 1%).

Optimal bit array length m:

m ≈ − (n · ln p) / (ln 2)²

Optimal number of hash functions k:

k ≈ (m / n) · ln 2

With those choices, this app gets m = 958 506 and k = 7. Memory for the bit buffer is on the order of m / 8 bytes (plus small object overhead) when using bitarray.

Estimated false-positive rate after inserting nins keys (approximation):

P(false positive) ≈ ( 1 − e^(−k · nᵢₙₛ / m) )^k

As the bit array fills, this probability rises toward the design target.

Example: “empty memory,” then saurabh

Picture the bit array starting as all zeros-there are no stored names, only bits. You add the first name saurabh: compute h₁(saurabh), h₂(saurabh), then the k indices above and set those bits to 1 (some may already be 1 from chance; that is fine).

You then search for saurabh using the same hash formulas. If every probed bit is 1, the answer is “possibly present”-and because you just inserted it, that is a true positive. If any probed bit is 0, the answer is “definitely not present.”
